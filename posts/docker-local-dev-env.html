背景

新项目往往要同时依赖 MySQL、Redis、Nginx 等多个服务。逐个手动安装、 配置、升级，既耗时又容易让不同项目的依赖互相冲突（比如两个项目需要 不同版本的 Redis）。本文记录用 Docker 把整套依赖"装进容器"，让本地 环境一条命令起停、跨机器一致的实践过程。

方案选型

搭建本地开发环境，主流有三种思路：

方案 优点 缺点
直接安装到宿主机 简单直接，零学习成本 依赖冲突、卸载残留、版本难切换
虚拟机（VirtualBox/VMware） 隔离彻底，接近生产 资源占用高、启动慢、共享目录麻烦
容器（Docker） 轻量秒级启动、版本隔离、配置即代码 需要理解镜像/容器/数据卷等概念

最终选择 Docker：环境描述以 Dockerfile 与 docker-compose.yml 形式 提交进仓库，新同事 clone 后一条命令即可还原环境，彻底告别"在我机器上 能跑"。

实施过程

安装 Docker Desktop（Windows）

  1. 访问 Docker 官网下载 Docker Desktop for Windows 安装包。
  2. 安装时勾选使用 WSL 2 后端（Windows 10/11 需要先启用 WSL： wsl --install）。
  3. 安装完成后重启，运行 docker version 验证：
docker version

输出 Client 与 Server 两部分都正常显示版本号，说明安装成功 （Server 缺失通常表示 Docker 引擎未启动）。

  1. 确认版本信息：
docker info

常用命令速查

# 镜像
docker pull redis:7        # 拉取镜像
docker images              # 查看本地镜像
docker rmi redis:7         # 删除镜像

# 容器
docker run -d --name my-redis -p 6379:6379 redis:7
docker ps                  # 查看运行中容器
docker ps -a               # 查看全部容器
docker stop my-redis       # 停止
docker start my-redis      # 启动
docker rm my-redis         # 删除容器（需先停止）

# 进入容器 / 查看日志
docker exec -it my-redis sh
docker logs -f my-redis

# 清理
docker system prune        # 清理悬空镜像与停止的容器

用 docker-compose 编排多服务

单条 docker run 参数一多就难以维护，改用 docker-compose.yml 声明式 管理。示例：一个 Go 应用 + MySQL + Redis 的开发环境。

# docker-compose.yml
services:
  mysql:
    image: mysql:8.0
    container_name: dev-mysql
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: app
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 5s
      retries: 10

  redis:
    image: redis:7
    container_name: dev-redis
    ports:
      - "6379:6379"

  app:
    build: .
    container_name: dev-app
    ports:
      - "8080:8080"
    environment:
      DB_DSN: root:root@tcp(mysql:3306)/app?charset=utf8mb4
      REDIS_ADDR: redis:6379
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_started
    volumes:
      - .:/app          # 本地代码热挂载
    command: go run main.go

volumes:
  mysql-data:

要点：

  • 容器间通过服务名（mysql、redis）互相访问，而不是 localhost；
  • depends_on 配合 healthcheck，保证 MySQL 就绪后再启动应用；
  • 数据卷 mysql-data 让数据库文件与容器生命周期解耦，删容器不丢数据。

启动与使用：

docker compose up -d       # 后台启动全部服务
docker compose ps          # 查看服务状态
docker compose logs -f app # 跟随应用日志
docker compose down        # 停止并移除容器（数据卷保留）
docker compose down -v     # 连同数据卷一起删除（谨慎！）

踩坑记录

端口被占用：port is already allocated

本机已安装原生 MySQL 时，容器 3306 映射会冲突。解法：改宿主端口 "3307:3306"，或停用宿主机原生服务；容器间通信不受影响，因为走的是 服务名。

WSL 2 下代码挂载的写入性能慢

volumes 直接把 Windows 目录挂进容器时，频繁读写（如编译产物、 node_modules）会明显变慢。解法：把依赖目录用命名卷覆盖，例如 app 服务中追加 node_modules:/app/node_modules；纯日志与中间产物 放到卷内。

Windows 文件权限问题：文件出现在 WSL 中为 -rwxrwxrwx

通过 Windows 共享文件在容器里总是全权限位，git 会误判为"可执行"而 告警。解法：容器内生成的文件尽量写在命名卷里，避免写回 Windows 文件系统；或在项目根放 .gitattributes 显式声明。

docker compose 与 docker-compose 命令不一致

新版 Docker Desktop 推荐 docker compose（子命令形式，V2），旧教程 多为 docker-compose（独立二进制）。两个版本都可用，但注意：新版 docker compose up 在代码变更后不会自动重建镜像，需要

docker compose up -d --build

修改了 docker-compose.yml 但服务没变化

docker compose up -d 是增量式的，配置或 Dockerfile 变化后要显式加 --build 重建，而不是只依赖 restart：

docker compose up -d --build --force-recreate

结语

Docker 把"搭环境"从重复劳动变成了可提交、可复现的配置代码：git clone 之后执行 docker compose up -d，一套一致的环境就绪。下一步计 划把本文示例改造成完整的开发/测试双环境 compose 文件，并把镜像 pull 也固化进项目文档，进一步缩短新成员上手时间。

背景

AI 写代码越来越顺手，原型几小时就能出来。但「能跑」和「可靠」之间 隔着一条沟：后端配置、依赖、数据库这几块最容易埋雷，而 Vibe Coding 恰恰容易在这几块翻车——因为 AI 不会主动告诉你它把密钥写进了哪一行。

先立几条安全规矩

配置：密钥别进代码

密钥、Token 一律环境变量读取，示例配置只放占位符。有人问我「之前 明文存过怎么办」，答案是轮换——不是删掉重新写，是把旧值作废换新的， 因为明文可能已经被人扫走了。

日志：知道该记什么，更要知道不该记什么

请求日志记方法、路径、状态码、耗时就够；错误日志留异常栈和错误码； 数据库日志查慢查询。密码、手机号、完整请求体，一律不进日志。说白了， 日志是给排障用的，不是给事故调查添堵的。

依赖：高危漏洞要追，升级要稳

Log4j 那种漏洞一出，全行业都在补。但升级不是无脑 pip install -U， 登录、数据库连接这类核心依赖，升级前先确认行为没变，再上回归。

数据库：软删除、事务、后端鉴权

核心数据软删除，物理删除基本没有理由用。多表操作包在事务里，别让 中间步骤失败后留下半个状态。权限校验必须在后端做——前端藏按钮只是 藏了个寂寞，接口照样能被直接调。

def soft_delete(session, user_id: int) -> None:
    with session.begin():
        user = session.get(User, user_id)
        user.deleted_at = datetime.now()

验收：三种场景都要测

正常访问要测，未登录要测，登录了但越权也要测。全程走接口验证， 不是浏览器里点两下就算过。测完留日志留记录，验收才有依据。

顺手的一套工具链

开发这边：superpowers 梳理想法，frontend_design 调页面，Playwright MCP 做浏览器自动化测试，写内容之前先想清楚再动手。

内容那边：agent-reach 找资料，humanizer-zh 去 AI 味，content-risk-detector 查敏感词。我一般写完后过一遍 humanizer，再让敏感词检查扫一遍，发出去 才放心。

最后用 skill-creator 把整套流程固化成 skill——开发、测试、内容生产、 发布，一条命令跑完。日常八成以上的活儿，这几个工具组合下来都覆盖了。

一些教训

最开始的坑是示例配置里直接写了真实密钥，还好是个人项目，发现后立刻 轮换。后来给接口补测试时才发现，只测正常流程根本不够，未登录和越权 两种场景一测就漏了几个洞。

结语

Vibe Coding 的安全没那么玄乎，不用堆复杂框架。关键是把风险点想清楚、 规则定死、验证留证据。也别只问 AI「这样安全吗」——让它把风险、规则、 验证依据讲清楚，比一句「安全」靠谱得多。

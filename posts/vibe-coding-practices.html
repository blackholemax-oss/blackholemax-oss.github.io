背景

Vibe Coding（氛围编程）让 AI 快速产出原型与功能，但「能跑」不等于 「可靠」。后端底层有三类隐蔽风险常被忽略：配置、依赖、数据库。 同时，如何用 AI 工具把「开发 → 测试 → 内容生产」串成完整工作流， 也是值得沉淀的工程经验。

方案选型：两条主线

本文整理为两条并行的实践主线：

主线 目标 手段
后端安全规范 堵住隐蔽风险 五条刚性规范（见下）
AI 工具链工作流 覆盖九成场景 按场景组合专用工具

后端安全五条规范

1. 配置安全

密钥、Token 绝不硬编码，统一用环境变量读取；示例配置只留占位符。 曾明文存过密钥的仓库要立即轮换（不是删除，是换新值）。

# config.example.yaml —— 只允许占位符
db:
  password: "${DB_PASSWORD}"
  secret: "${JWT_SECRET}"

2. 日志安全

密码、手机号等敏感信息必须脱敏；分清各类日志的职责：

日志类型 该记什么 不该记什么
请求日志 方法、路径、状态码、耗时 请求体、Token
错误日志 异常栈、错误码、上下文 ID 完整 SQL 与参数
数据库日志 慢查询、锁等待 用户敏感字段明文

3. 依赖安全

定期检查框架与 SDK 漏洞（Log4j 一类高危漏洞影响面极广）；升级前 先确认不影响现有功能；登录、数据库连接类核心依赖重点盯防。

4. 数据库安全

  • 核心数据用软删除，别物理删
  • 多表操作必须用事务保证一致性
  • 读写删都要校验身份与权限，不能只靠前端隐藏按钮——后端是最后防线
# 软删除而非 DELETE
def soft_delete(session, user_id: int) -> None:
    with session.begin():  # 事务保证一致性
        user = session.get(User, user_id)
        user.deleted_at = datetime.now()

5. 验收规范

接口做「业务 + 安全」双重测试：正常访问、未登录、越权三种场景 都要覆盖；全程走接口验证（不是点了页面就算过）；留好日志与 数据记录作为验收证据。

AI 工具链工作流

按场景组合工具，覆盖九成使用场景：

场景 工具 职责
产品开发 superpowers 梳理想法、规划任务
产品开发 frontend_design 优化页面设计
产品开发 Playwright MCP 浏览器自动化测试
自媒体 agent-reach 搜集资料
自媒体 humanizer-zh 去除 AI 味
自媒体 content-risk-detector 敏感词检测
流程串联 skill-creator 一键跑完整工作流

典型链路：superpowers 理清需求 → 开发 → frontend_design 调优 → Playwright MCP 回归测试 → 产出内容用 humanizer-zh 润色 → content-risk-detector 把关 → skill-creator 固化为可复用流程。

踩坑记录

  • 曾明文存储密钥到示例配置 → 立即轮换密钥并改为占位符
  • 只测正常流程、跳过未登录/越权 → 验收必须三场景齐测
  • 依赖盲目升级导致登录模块故障 → 升级前先做影响评估与回归

结语

Vibe Coding 的安全不靠堆复杂代码，关键是明确风险在哪、规则咋定、 证据咋留。让 AI 说清楚风险、规则和验证依据，而不是只问「安不安全」。 工具链的意义同样在此：把重复环节固化为流程，让每次交付都可复现、可验证。

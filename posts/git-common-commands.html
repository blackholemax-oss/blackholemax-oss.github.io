引言

Git 是现代开发的必备工具，但命令繁多，新手往往记不住。 本文整理四类最常用的命令场景，配合示例，随用随查。

基础提交流程

初始化仓库并完成第一次提交：

git init                    # 初始化仓库
git status                  # 查看工作区状态
git add README.md           # 暂存指定文件
git add .                   # 暂存全部改动
git commit -m "docs: 初始化" # 提交并附上说明
git log --oneline           # 查看提交历史

注意：git add 只把改动放进暂存区，git commit 才会真正 生成一个提交记录。养成「先 status、再 add、后 commit」的习惯， 能有效避免把多余文件提交进去。

分支管理

分支让多个功能并行开发互不干扰：

git branch                # 列出本地分支
git branch feature-login  # 创建新分支
git checkout feature-login  # 切换分支（旧命令）
git switch feature-login  # 切换分支（新命令，更直观）
git checkout -b fix-bug   # 创建并切换到新分支
git branch -d fix-bug     # 删除已合并的分支
git merge feature-login   # 把分支合并到当前分支

建议每个功能或 bug 修复都开独立分支，完成后合并回主干， 避免在主干上堆砌半成品提交。

撤销操作

撤销是新手最怕出错的部分，记住三个工具：

git restore file.txt      # 丢弃工作区改动，回到暂存区/HEAD 状态
git restore --staged file.txt  # 把文件移出暂存区（不丢改动）
git commit --amend -m "修正后的说明"  # 修改最近一次提交信息
git reset --soft HEAD~1   # 撤销最近一次提交，改动保留在暂存区
git reset --hard HEAD~1   # 彻底撤销提交和改动（慎用！）

--hard 会永久丢弃改动，使用前务必确认。如果提交已经推到 远程，一般改用 git revert <commit> 生成一个反向提交来 "安全撤销"。

远程协作

与他人协作，先关联远程仓库，再推送与拉取：

git remote add origin https://github.com/you/repo.git
git remote -v             # 查看远程仓库
git push -u origin main   # 首次推送，建立关联
git push                  # 之后可直接推送
git pull                  # 拉取远程更新并合并
git fetch origin          # 只拉取更新，不自动合并
git clone https://github.com/you/repo.git  # 克隆现有仓库

git fetch 与 git pull 的区别：fetch 只把远程更新下载到本地， 由你决定何时合并；pull 等于 fetch + merge，一步到位。推送前先 pull，能减少合并冲突。

结语

以上命令覆盖了日常开发 80% 的 Git 操作。遇到记不住的细节， 可以用 git help <命令> 查看官方文档。写代码之外，也别忘了 用 git log --graph 欣赏一下自己分支史。欢迎在评论区分享 你的常用 Git 技巧。
